# AI Chat Hub 产品设计方案

## 1. 产品定位

AI Chat Hub 是一个运行在 uTools 内的多平台 AI 对话聚合插件。它不直接把第三方网页嵌入主界面，而是在后台通过浏览器实例访问各 AI 平台网页，提取对话内容后以统一 UI 展示；同时预留官方 API / OpenAI-compatible API 的接入能力，后续可以逐步从网页自动化迁移到稳定 API。

首期重点解决三件事：

- 一个入口同时使用 DeepSeek、通义 / 千问、Kimi、豆包等网页 AI 平台。
- 保存跨平台历史记录，能按标题、平台、链接、摘要快速找回并继续提问。
- 支持对比模式，把同一个问题发送到两个平台并排查看回答。

## 2. 目标用户与核心场景

目标用户：

- 经常在多个 AI 网页之间切换的个人用户。
- 希望对比不同模型答案质量的内容、开发、运营、研究类用户。
- 希望保留对话线索，但不想分别维护多个平台历史记录的用户。

核心场景：

- 快速新建对话：打开插件后默认进入新对话，选择默认平台并输入问题。
- 继续历史对话：从左侧历史列表搜索或筛选记录，重新打开平台会话 URL，接着问。
- 双平台对比：选择主平台和对比平台，一个输入同时发送到两个后台浏览器实例，主界面分屏展示两份回答。
- 平台管理：启用 / 停用平台、设置默认平台、配置网页入口和未来 API 参数、管理登录状态。
- 历史管理：查看、搜索、删除历史记录，查看平台名、标题、链接和回答摘要。

## 3. 信息架构

插件包含两个主模块：

- 对话页
- 设置页

对话页结构：

- 顶部平台栏：Logo / 插件入口、当前主平台 Tab、可选对比平台 Tab、新对话按钮、设置入口。
- 左侧历史栏：默认可收起；展示历史记录标题、平台、时间、摘要片段；支持搜索、按平台过滤、点击切换。
- 中间对话区：展示用户问题和 AI 回答；普通模式为单列；对比模式为左右双列或小屏 Tab 切换。
- 底部输入区：多行输入、发送按钮、停止按钮、附件入口预留、当前发送目标提示。

设置页结构：

- 左侧设置栏目：AI 平台管理、历史记录管理。
- 右侧设置内容：根据栏目显示表格、表单、搜索和批量操作。

## 4. 对话页设计

### 4.1 普通模式

默认进入普通模式：

- 当前平台使用用户设置的默认平台。
- 如果没有默认平台，使用启用列表里的第一个平台，并提示用户在设置中指定默认平台。
- 点击顶部平台 Tab 可以切换目标平台；切换时默认开启一个新对话。
- 从历史记录进入时，顶部平台自动切到该历史所属平台，对话 URL 作为恢复入口。

发送流程：

1. 用户输入问题。
2. 前端创建本地消息草稿，状态为 `sending`。
3. 后台服务打开对应平台会话 URL 或新对话入口。
4. 自动输入问题并提交。
5. 轮询或提取网页回答内容，持续更新前端消息。
6. 完成后生成 / 更新标题、摘要、平台名、链接和时间。

### 4.2 对比模式

用户在顶部选择一个对比平台后进入对比模式：

- 大屏：主平台和对比平台左右分栏。
- 小屏：保持单列输入区，回答区使用平台 Tab 切换。
- 同一个问题同时发送到两个平台。
- 两侧状态独立：排队、登录失效、发送中、生成中、完成、失败。
- 如果一个平台失败，不影响另一个平台继续生成。

对比模式历史记录有两种存储方式：

- 推荐：创建一个 `compareSession`，下面挂两个平台的 `conversation` 记录，便于回放双列视图。
- 兼容：每个平台也各自生成独立历史，便于未来按平台继续追问。

## 5. 设置页设计

### 5.1 AI 平台管理

平台列表字段：

- 平台名称
- 启用状态
- 默认平台
- 对比候选状态
- 接入方式：网页 / API
- 登录状态
- 最近检测时间
- 操作：登录 / 检测 / 编辑

平台配置项：

- 基础信息：平台 ID、名称、图标、描述。
- 网页配置：新对话 URL、历史会话 URL 规则、登录 URL、选择器配置、是否支持继续会话。
- API 预留：Base URL、API Key、模型名、请求格式、流式开关、代理配置。
- 对话能力：是否支持附件、是否支持联网、是否支持文件解析、是否支持多轮 URL 恢复。
- 风险标记：是否需要验证码、是否频繁变更 DOM、是否强登录。

默认内置平台：

- DeepSeek: `https://chat.deepseek.com/`
- Qwen: `https://chat.qwen.ai/`
- 千问: `https://www.qianwen.com/`
- Kimi: `https://www.kimi.com/`
- 豆包: `https://www.doubao.com/chat/`

登录授权管理：

- 登录优先使用可视化 `ubrowser.show()` 方式，让用户在真实网页里扫码或输入账号。
- 登录完成后依赖 uTools ubrowser 的 cookie / session 复用。
- 如需持久化 cookie，只在用户明确授权后使用加密存储，并提供清除入口。
- API Key 使用加密存储，不放入普通 `utools.db` 文档。

### 5.2 历史记录管理

历史列表字段：

- 标题
- 回答摘要
- AI 平台名
- 会话链接
- 创建时间
- 最后更新时间
- 消息数
- 接入方式

能力：

- 搜索：标题、平台、摘要、最近问题、链接。
- 筛选：平台、时间范围、普通 / 对比、网页 / API。
- 操作：打开继续、复制链接、导出、删除、批量删除。
- 维护：摘要重新生成、失效链接标记、登录失效提示。

摘要生成策略：

- 默认免费方案：本地规则摘要，基于最近一轮问答提取前几句、关键词和结论句，不调用付费模型。
- 增强方案：如果用户启用了 uTools AI 或配置了自己的 API，可用模型生成更自然摘要。
- 兜底方案：回答过短时直接截取回答片段；回答失败时记录错误原因。

## 6. 状态与异常设计

常见状态：

- 未登录：提示去登录，提供“打开登录窗口”。
- 会话恢复失败：保留历史记录，提示使用新对话重新发送。
- 平台选择器失效：提示平台适配器需要更新。
- 生成超时：允许重试、停止、打开原网页排查。
- 平台限流：保留问题草稿，提示稍后重试。

错误展示原则：

- 不把底层异常直接暴露给普通用户。
- 在开发模式中保留平台、URL、选择器、阶段、错误堆栈，便于维护适配器。
- 对比模式下错误只占据对应平台回答区，不阻断另一个平台。

## 7. MVP 范围

第一阶段建议只做：

- Vue 主界面：对话页、历史栏、设置页骨架。
- 平台配置 CRUD。
- 历史记录 CRUD 和搜索。
- 一个网页平台适配器的端到端验证，建议先选 DOM 相对简单且账号已登录的平台。
- 登录检测、发送问题、提取最终回答、保存标题 / URL / 摘要。
- 对比模式先支持两个已验证平台，不追求所有平台一次性适配。

暂不做：

- 复杂富文本 / Markdown 完整还原。
- 跨设备同步冲突处理的完整体验。
- 自动破解验证码、绕过风控或规避平台限制。
- 所有平台的完整历史列表同步。

## 8. 迭代路线

### V0.1 原型

- 完成页面布局和本地数据结构。
- 手动维护历史记录。
- 完成平台管理表单。

### V0.2 单平台网页自动化

- 使用 uTools `ubrowser` 完成单平台登录检测、发送问题、抓取回答。
- 保存会话 URL 和摘要。
- 支持继续历史对话。

### V0.3 对比模式

- 两个平台并发发送。
- 双列回答渲染。
- 对比历史记录存储。

### V0.4 稳定性

- 适配器健康检查。
- 选择器版本管理。
- 错误日志和调试工具。
- 历史摘要重建。

### V1.0 API 混合接入

- 对支持 API 的平台新增 API 模式。
- API 优先，网页自动化作为无 API 或个人网页账号的补充。
- 平台能力统一抽象，前端无感切换。
